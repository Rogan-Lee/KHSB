# 사용 통제 장비 설치 안내

시설 와이파이에서 앱·사이트를 막으려면 시설 안에 작은 장비 한 대가 필요합니다. 이 문서는 그 장비를 사서 설치하는 사람을 위한 안내입니다. 터미널에 명령 한 줄을 붙여 넣을 수 있으면 따라 할 수 있습니다.

## 어떻게 동작하나

```
학생 기기 ──(주소 물어봄)──▶ 시설 장비: AdGuard Home ──▶ 인터넷
                                  ▲ 규칙을 넣어 줌
                             동기화 에이전트
                                  ▲ 30초마다 정책을 받아 옴
                             스터디룸 매니저 서버
```

- 기기가 사이트에 접속하려면 먼저 "이 이름의 주소가 뭐야?"(DNS)를 물어봅니다. 시설 장비의 AdGuard Home 이 그 질문을 받아, 막아야 할 이름에는 답을 주지 않습니다.
- 무엇을 막을지는 대시보드의 **사용 통제** 화면에서 정합니다. 장비의 에이전트가 30초마다 서버에서 정책을 받아 AdGuard Home 에 넣습니다.
- 장비가 서버 쪽으로만 접속하므로 공유기 포트를 열 필요가 없습니다.

## 비용

| 항목 | 비용 |
|---|---|
| AdGuard Home | 무료 (오픈소스, 계정·라이선스·결제 없음) |
| 동기화 에이전트 | 무료 (대시보드가 내려 줌) |
| 장비 1대 | 구매비만. 남는 PC·노트북이 있으면 0원 |
| 전기료 | 월 1천 원 안팎 (24시간 켜 두는 소형 장비 기준 추정) |

AdGuard 에는 유료 서비스(AdGuard DNS)도 있지만 이 구성에서는 쓰지 않습니다.

## 준비물

| 항목 | 내용 |
|---|---|
| 장비 | 미니 PC, 쓰던 PC, 라즈베리파이 4 이상 중 1대. **24시간 켜 둡니다.** 성능은 거의 필요 없습니다(메모리 2GB 면 충분). |
| 운영체제 | 윈도우 10·11, 우분투 24.04, 데비안 12, 라즈베리파이 OS(64-bit) 중 하나 |
| 연결 | 공유기에 **유선**으로 연결합니다. 와이파이 연결은 끊기면 시설 전체 인터넷이 멈춥니다. |
| 공유기 | 관리자 화면에 들어가 DHCP 의 DNS 주소를 바꿀 수 있어야 합니다. |

어떤 운영체제로 할지는 이렇게 고릅니다.

- **윈도우 PC 를 그대로 쓰기**: 미니 PC 는 대부분 윈도우가 깔려 나오므로 운영체제를 새로 넣지 않아도 됩니다. 쓰던 PC 도 됩니다. 다만 이 PC 가 꺼지거나 절전에 들어가거나 윈도우 업데이트로 재부팅되는 동안에는 시설 와이파이의 인터넷이 멈춥니다. 사람이 쓰다가 끄는 PC 보다는 켜 두기만 하는 PC 가 맞습니다.
- **리눅스로 쓰기**: 켜 두고 잊어버리기에는 리눅스가 더 조용합니다(재부팅을 스스로 하지 않음). 미니 PC 에는 [우분투 서버](https://ubuntu.com/download/server) 설치 USB 로, 라즈베리파이에는 [Raspberry Pi Imager](https://www.raspberrypi.com/software/) 로 "Raspberry Pi OS Lite (64-bit)"를 넣습니다. 설치할 때 SSH 를 켜 두면 다른 PC 에서 접속해 명령을 붙여 넣을 수 있습니다.

## 설치 순서

### 1. 대시보드에서 장비 등록

대시보드 **사용 통제 > 장비 > 장비 등록**에서 장비 이름을 넣고 등록하면 설치 명령이 한 번 표시됩니다. 장비의 운영체제(윈도우·리눅스)를 고르고 복사해 둡니다.

### 2. 장비에서 설치 명령 실행

**윈도우**: 시작 버튼을 우클릭해 **터미널(관리자)** 또는 **Windows PowerShell(관리자)** 를 열고 붙여 넣습니다. 이런 모양입니다.

```powershell
$env:SRM_URL='https://대시보드-주소'; $env:SRM_TOKEN='srmag_...'; iex ([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData("$env:SRM_URL/access-agent/install.ps1")))
```

**리눅스**: 터미널에 붙여 넣습니다.

```sh
curl -fsSL https://대시보드-주소/access-agent/install.sh | sudo SRM_URL=https://대시보드-주소 SRM_TOKEN=srmag_... sh
```

몇 분 걸리고 `설치가 끝났습니다` 와 함께 **이 장비 주소**가 나옵니다. 대시보드의 장비 탭에 **연결됨**이 표시되는지 확인합니다.

여기까지는 아무 기기도 영향을 받지 않습니다.

### 3. 공유기 설정

공유기 관리자 화면의 DHCP 설정에서 두 가지를 합니다. 이 단계를 하면 차단이 시작됩니다.

1. 이 장비에 항상 같은 주소가 가도록 **주소를 예약**합니다.
2. **기본 DNS 를 장비 주소**로 바꿉니다. 보조 DNS 는 비우거나 같은 장비 주소를 넣습니다. 보조 DNS 에 통신사나 구글 주소(8.8.8.8)가 남아 있으면 기기가 그쪽으로 물어봐 차단이 새어 나갑니다.

기기들은 와이파이에 다시 붙을 때 새 설정을 받습니다. 바로 확인하려면 기기의 와이파이를 껐다 켭니다.

### 4. 기기 배정

대시보드 **사용 통제 > 기기**에 와이파이에 붙은 기기가 나타납니다. 학생 기기는 학생에게 배정하고, 직원 PC·프린터·공유기는 **통제 제외**로 둡니다.

- 배정하지 않은 기기에도 전체 규칙은 적용됩니다. 배정은 학생별 규칙과 일시 해제를 위해 필요합니다.
- 통제 제외로 둔 기기에는 어떤 규칙도 적용되지 않습니다.

## 설치 명령이 하는 일

다시 실행해도 안전합니다(이미 된 단계는 건너뜁니다).

리눅스(`install.sh`) — 우분투 24.04 와 데비안 12 에서 끝까지 돌려 확인했습니다.

1. 서버 주소와 토큰이 맞는지 확인합니다. 틀리면 아무것도 설치하지 않고 멈춥니다.
2. Node.js 가 없거나 18 미만이면 설치합니다.
3. AdGuard Home 을 `/opt/AdGuardHome` 에 설치하고 초기 설정을 합니다. 관리자 계정(아이디 `srm`, 비밀번호는 무작위)을 만들고, 관리 화면은 3000번, DNS 는 53번 포트로 엽니다. 우분투의 systemd-resolved 가 53번을 쓰고 있으면 그 대기 기능만 끕니다.
4. 에이전트를 `/opt/srm-access-agent` 에 받고 설정 파일(`.env`, 소유자만 읽기)을 씁니다.
5. 서버 정책을 한 번 넣어 본 뒤 `srm-access-agent` 서비스로 등록합니다. 재부팅해도 자동으로 켜집니다.

윈도우(`install.ps1`) — 같은 순서이고 다른 점만 적습니다. 서버 확인부터 첫 동기화까지의 흐름은 PowerShell 로 돌려 확인했지만, **윈도우에만 있는 단계(서비스·방화벽·예약 작업)는 실제 윈도우에서 아직 돌려 보지 못했습니다.** 처음 설치할 때 화면에 나온 내용을 남겨 두면 문제가 있을 때 바로 고칠 수 있습니다.

- AdGuard Home 은 `C:\AdGuardHome` 에 윈도우 서비스로 설치합니다. 관리 화면은 이 PC 에서만 열립니다(`http://127.0.0.1:3000`).
- 방화벽에서 DNS(53번) 들어오는 연결을 허용합니다. 와이파이 기기들이 이 PC 에 주소를 물어봐야 하기 때문입니다.
- 에이전트는 `C:\srm-access-agent` 에 두고, 전용 `node.exe` 를 함께 받습니다(PC 에 Node.js 를 설치하지 않습니다).
- "컴퓨터 시작 시 실행" 예약 작업(`SRM Access Agent`)으로 등록합니다. 로그인하지 않아도 돕니다.
- 전원이 연결된 동안 절전·최대 절전에 들어가지 않게 바꿉니다.

AdGuard Home 을 이미 직접 설정해 쓰고 있는 장비라면 관리자 계정을 함께 넘깁니다.

```sh
curl -fsSL https://대시보드-주소/access-agent/install.sh | sudo SRM_URL=... SRM_TOKEN=... ADGUARD_USER=아이디 ADGUARD_PASSWORD=비밀번호 sh
```

윈도우에서는 명령 맨 앞에 `$env:ADGUARD_USER='아이디'; $env:ADGUARD_PASSWORD='비밀번호';` 를 붙입니다. 관리 화면 포트가 3000 이 아니면 `ADGUARD_URL`(`http://127.0.0.1:포트`)도 같은 방식으로 넘깁니다.

## 설치 뒤 꼭 확인할 것

차단은 "주소를 물어보는 길"을 막는 방식이라, 그 길을 돌아가면 뚫립니다. 아래를 맞춰 두면 대부분 막힙니다.

| 확인할 것 | 이유 | 방법 |
|---|---|---|
| 공유기의 IPv6 끄기 | IPv6 로는 기기가 통신사 DNS 를 직접 받아 장비를 거치지 않습니다. | 공유기 관리자 화면 > IPv6 사용 안 함 |
| 외부 DNS 직접 접속 막기 | 기기에서 DNS 를 8.8.8.8 로 직접 바꾸면 장비를 건너뜁니다. | 공유기 방화벽에서 장비 주소를 뺀 나머지의 외부 53·853 포트를 차단 (지원하는 공유기만) |
| 추가 공유기는 AP(브리지) 모드 | 공유기 모드로 물린 AP 뒤의 기기는 전부 한 대로 보여 기기별 통제가 안 됩니다. | AP 설정에서 브리지·AP 모드 선택 |
| 학생 기기의 '비공개 Wi-Fi 주소' | '순환'이면 기기 주소가 바뀌어 배정이 풀립니다. 이때도 전체 규칙은 그대로 적용됩니다. | 이 와이파이에서는 '고정'으로 |

막을 수 없는 것도 있습니다.

- **LTE·5G 데이터, 핫스팟**: 시설 와이파이를 거치지 않습니다. 휴대폰 제출과 함께 운영해야 합니다.
- **VPN 앱**: 이미 설치돼 연결된 VPN 은 막지 못합니다.
- **인터넷이 필요 없는 앱**: 내려받아 둔 영상, 오프라인 게임.
- **주소를 IP 로 직접 적는 접속**과 일부 앱의 고정 서버.

암호화 DNS(DoH·DoT)와 iCloud 비공개 릴레이는 대시보드의 **우회 방지**가 켜져 있으면 함께 막습니다.

## 운영 중 알아 둘 것

- **반영 시간**: 대시보드에서 바꾼 내용은 30초 안에 장비에 들어갑니다. 풀어 주는 것은 곧바로 통합니다. 막는 것은 기기가 이미 받아 둔 주소를 잠시(보통 몇 분) 더 쓸 수 있어, 방금 보던 사이트는 조금 뒤에 막힙니다.
- **서버와 끊겼을 때**: 마지막으로 받은 정책을 유지합니다. 10분 넘게 끊기면 일시 허용(학생에게 잠깐 풀어 준 것)을 닫습니다.
- **장비가 꺼졌을 때**: 주소를 답해 줄 곳이 없어 시설 전체 인터넷이 멈춥니다. 급할 때는 공유기 DNS 를 원래대로 돌리면 인터넷은 되지만 차단은 꺼집니다.
- **윈도우 장비**: 윈도우 업데이트가 재부팅하는 몇 분 동안 인터넷이 멈춥니다. 설정 > Windows 업데이트 > 고급 옵션의 **사용 시간**을 운영 시간으로 맞춰 두면 그 시간에는 재부팅하지 않습니다. 노트북이라면 덮개를 닫아도 절전에 들어가지 않게 해 둡니다.
- **AdGuard Home 관리 화면**: 리눅스는 `http://장비주소:3000`, 윈도우는 그 PC 에서 `http://127.0.0.1:3000`. 계정은 에이전트 폴더의 `.env` 에 있습니다(리눅스 `sudo cat /opt/srm-access-agent/.env`, 윈도우 `C:\srm-access-agent\.env`). 평소에는 들어갈 일이 없습니다.
- **AdGuard Home 에 직접 적은 규칙**: `! srm:begin` 과 `! srm:end` 사이는 에이전트가 덮어씁니다. 직접 쓰는 규칙은 그 밖에 적으면 유지됩니다.
- **AdGuard Home 클라이언트**: 이름이 `srm-` 으로 시작하는 클라이언트와 `user_regular` 태그는 에이전트가 관리합니다. 직접 만든 클라이언트에는 `user_regular` 태그를 쓰지 마세요. 전체 규칙에서 빠집니다.
- **인터넷 전체 잠금 중에도 열리는 주소**: 대시보드 주소, 와이파이 연결 확인, 푸시 알림. 학생 앱이 대시보드와 다른 주소로 접속한다면 서버 환경변수 `ACCESS_ALWAYS_ALLOW` 에 쉼표로 구분해 넣습니다.
- **AdGuard Home 업데이트**: 관리 화면에서 버튼으로 합니다. 새 앱·서비스가 목록에 추가됩니다. 대시보드에 "장비가 모르는 서비스" 경고가 뜨면 업데이트합니다.
- **에이전트 업데이트**: 아래 명령으로 새 파일을 받아 다시 시작합니다.

```sh
cd /opt/srm-access-agent && sudo sh -c '. ./.env && curl -fsSL "$SRM_URL/access-agent/agent.mjs" -o agent.mjs && systemctl restart srm-access-agent'
```

윈도우에서는 설치 명령을 다시 실행하면 됩니다(토큰은 그대로 쓸 수 있습니다).

## 로그 보기와 문제 해결

```sh
sudo journalctl -u srm-access-agent -n 50 --no-pager                  # 리눅스
```

```powershell
Get-Content C:\srm-access-agent\agent.log -Tail 50                    # 윈도우
```

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `[설치 중단] 토큰이 맞지 않습니다` | 명령을 잘못 붙였거나 장비가 대시보드에서 삭제됨 | 장비를 다시 등록해 새 명령으로 실행 |
| `[설치 중단] 서버가 307(또는 404) 로 응답했습니다` | 대시보드에 이 기능이 아직 배포되지 않음 | 배포 뒤 다시 실행 |
| `[설치 중단] 53번 포트(DNS)를 쓸 수 없습니다` | 다른 DNS 프로그램(dnsmasq 등)이 돌고 있음 | 그 프로그램을 끄고 다시 실행 |
| `서버 연결 실패 … 401` | 토큰이 무효가 됨 | 장비를 다시 등록하고 설치 명령을 다시 실행 |
| `서버 연결 실패: fetch failed` | 인터넷 또는 서버 주소 문제 | 장비에서 `curl -I 대시보드-주소` 확인 |
| `AdGuard Home 적용 실패 … 401`·`403` | AdGuard Home 비밀번호를 바꿨음 | `.env` 의 `ADGUARD_USER`·`ADGUARD_PASSWORD` 를 고치고 서비스 다시 시작 |
| `AdGuard Home 적용 실패: fetch failed` | AdGuard Home 이 꺼져 있음 | `sudo systemctl status AdGuardHome` |
| 기기 탭이 비어 있음 | 기기가 아직 장비로 물어보지 않음 | 공유기 DNS 를 바꿨는지, 기기 와이파이를 다시 붙였는지 확인 |

`.env` 를 고친 뒤에는 다시 시작합니다. 리눅스는 `sudo systemctl restart srm-access-agent`, 윈도우는 관리자 PowerShell 에서 `Stop-ScheduledTask 'SRM Access Agent'; Start-ScheduledTask 'SRM Access Agent'`.

## 제거

```sh
sudo systemctl disable --now srm-access-agent
cd /opt/srm-access-agent && sudo node agent.mjs --remove     # 에이전트가 넣은 규칙과 기기를 AdGuard Home 에서 지움
sudo rm -rf /opt/srm-access-agent /etc/systemd/system/srm-access-agent.service
```

윈도우에서는 관리자 PowerShell 에서 이렇게 합니다.

```powershell
Stop-ScheduledTask 'SRM Access Agent'; Unregister-ScheduledTask 'SRM Access Agent' -Confirm:$false
cd C:\srm-access-agent; .\node.exe agent.mjs --remove
Get-NetFirewallRule -DisplayName 'SRM AdGuard Home DNS*' | Remove-NetFirewallRule
cd \; Remove-Item -Recurse -Force C:\srm-access-agent
```

그다음 공유기의 DNS 를 원래 값으로 되돌립니다. 대시보드에서 장비를 삭제하면 토큰도 무효가 됩니다. AdGuard Home 까지 지우려면 `sudo /opt/AdGuardHome/AdGuardHome -s uninstall`(윈도우는 `C:\AdGuardHome\AdGuardHome.exe -s uninstall`) 뒤 그 폴더를 지웁니다.
