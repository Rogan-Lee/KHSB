## 3. 심사용 데모 계정

`scripts/seed-review-demo.ts`로 만든다. 가상 학생 "데모 학생" 1명과 그 학생에 딸린 계정 3개, 가입·탈퇴 시험용 학부모 초대 코드 2개(1회용, 90일)를 만든다. 기존 데이터는 건드리지 않고 `review-demo-` 접두어 레코드만 만들고 지운다.

| 계정 | 아이디 | 보이는 것 |
|---|---|---|
| 학생 | `appreview.student` | 출결 10일, 수행평가 4건, 질문 2건, 메시지, 멘토링 예정 |
| 학부모 | `appreview.parent` | 자녀 출결 달력, 멘토링 리포트 2건, 6·9월 모의고사 성적, 상벌점 |
| 직원 | `appreview.staff` | 컨설턴트 역할. 데모 학생만 담당: 수행평가(피드백 대기 1건), 메시지, 공지, 일정 |

- 직원 계정을 컨설턴트로 둔 이유: 멘토·운영조교 같은 오프라인 운영 역할은 입퇴실·좌석·학생 검색·순찰 화면에 재원생 전원이 나와 실제 학생 개인정보가 심사자에게 보인다. 컨설턴트는 담당 학생 범위만 보고, 전체 학생 API(`/staff/students`, `/attendance`, `/seat-map`, `/questions`, `/overview`)는 403이다. 공지·시설 일정·직원 이름(DM 목록)은 실제 데이터가 보인다.
- 데모 멘토 "김데모"는 퇴사 상태라 운영진 선택 목록에 뜨지 않고 로그인할 수 없다. 데모 직원은 활성 상태라 심사 기간에는 직원 목록에 보인다.
- **저장소가 공개**라 비밀번호·초대 코드는 커밋하지 않는다. 스크립트가 `.app-review/<project-ref>.md`(gitignore)에 계정 표와 붙여 넣기용 영문 심사 노트를 함께 쓴다.

```bash
# 저장소 루트에서
npx tsx --env-file=.env.development.local scripts/seed-review-demo.ts --apply   # 개발 DB
npx tsx --env-file=.env.local scripts/seed-review-demo.ts --apply --prod       # 운영 DB (사용자 실행)
npx tsx --env-file=.env.local scripts/seed-review-demo.ts --delete --prod      # 심사가 끝나면
```

- `--apply`를 다시 돌리면 데모 학생 데이터(심사자가 남긴 질문 등 포함)를 새로 만들고, 계정 비밀번호와 쓸 수 있는 초대 코드는 유지한다. 비밀번호를 바꾸려면 `--reset-passwords`(심사 중에는 금지).
- 개발 DB에서 확인한 것: 세 계정 로그인, 학생·학부모 화면 데이터, 초대 코드 가입 → 계정 삭제 후 `AuthUser`·`AuthAccount`·`ParentLink` 삭제, `--delete` 후 재생성.
- 심사 기간에 심사자가 보낸 질문·문의·점심 신청·직원 DM이 실제 운영 화면에 들어올 수 있다. "데모 학생"·"데모 직원" 건은 무시하도록 운영진에게 알린다.

Apple 개발자 계정이 독서실 명의가 아니면 `APP_REVIEW_DEVELOPER="<계정 명의>"` 를 한 번 붙여 실행한다 — "독서실을 대신해 올린다"는 문장이 6번 항목에 들어가고, 값은 `.app-review/<ref>.json` 에 남아 다음 실행에도 쓰인다(저장소가 공개라 명의는 코드에 적지 않는다).
- Apple 이 "심사 이력이 적은 계정" 추가 정보를 요청하면(2026-10-11) 같은 글을 답장에 쓰고, **실기기에서 찍은 화면 녹화**를 첨부한다. 녹화에는 앱 실행, 초대 가입, 계정 삭제, 로그인, 약관 동의, 신고·차단이 들어가야 한다.

## 5. 제출 전 셀프 점검

1. 미국 VPN을 켠 새 기기(또는 시뮬레이터)에서 초대 코드로 가입 → 주요 화면 → 계정 삭제까지 해 본다. 삭제 후 운영 DB에서 `AuthUser`와 `DevicePushToken`에 해당 행이 없는지 확인한다.
2. 앱 안의 링크와 버튼을 한 번씩 누른다: 고객센터, 전화 문의(iPad에서는 번호 복사), 개인정보처리방침, 비밀번호를 잊었어요.
3. Support URL과 개인정보처리방침을 로그아웃 상태의 휴대폰 브라우저에서 연다.
4. iPad 시뮬레이터에서 가로·세로·화면 분할로 실행해 로그인·역할별 홈 대시보드·사이드바 이동·계정 화면이 뜨는지 본다.
5. 권한 창 문구를 확인한다: 운영진 순찰 QR(카메라), 질문 사진 촬영(카메라), 사진 첨부(보관함).
6. 제출 직전에 데모 계정 세 개로 로그인해 데이터를 확인한다.

## 7. 집중 모드(스크린 타임) — 할 일 순서

학생이 앱에서 스스로 고른 앱·사이트를 잠그는 기능이다. 학생이 비밀번호로 끌 때까지 잠기고, 켜 둔 채 잊지 않게 2시간이 지나면 "아직 공부 중인가요?" 알림을 보내 3시간까지 답이 없으면 저절로 풀린다(앱이 꺼져 있어도 ActivityMonitor 확장이 푼다). "계속 공부하기"를 누르면 그때부터 다시 2·3시간. AppBlock 의 엄격 모드처럼 잠글 앱을 바꾸거나 끝내려면 학생이 정한 잠금 비밀번호(숫자 4~6자리)가 필요하고, 잊으면 강한선배 로그인 비밀번호로 앱 안에서 초기화한다(서버 `/api/mobile/v1/auth/verify-password` 는 맞다/틀리다만 답하고, 계정 단위 시도 제한이 걸려 있다). 처음 한 번 설정한 뒤에는 학생 앱 홈의 "바로 시작"으로 한 번에 켠다. iOS·iPadOS 18 이상만(아이폰·아이패드). 코드는 `apps/mobile/src/features/student-focus/`(공용·홈 카드)와 `apps/mobile/src/app/(student)/focus.tsx`(설정 화면). 아래는 **계정 주인이 직접 하는 일**이다(2026-11-04 기준).

**약관 때문에 정한 범위.** 애플 Family Controls 는 "부모가 가족 공유로 자녀 기기 관리" 또는 "개인이 자기 기기 관리(집중·생산성)"에만 쓸 수 있고, 조직(organizational settings)이 쓰는 것, 다른 성인의 기기를 관리하는 것, 사용 정보를 그 개인 밖으로 보내는 것을 금지한다. 그래서 집중 모드는 학생 본인만 켜고 끄며, 무엇을 골랐는지·켰는지는 서버로 보내지 않는다. **시설이 학생에게 켜라고 강제하거나 대시보드에서 확인하는 기능은 만들지 않는다.** 시설 안 차단은 와이파이 차단([access-agent/README.md](../access-agent/README.md))이 맡는다.

아이폰에서는 차단 화면과 "시간이 지나면 풀기"를 앱 본체가 아니라 앱 안에 들어가는 부품(확장) 3개가 맡아서, 본체까지 ID 4개에 권한이 필요하다.

### 라. 안드로이드 — 아직 없음

안드로이드 앱에는 집중 모드가 없다(메뉴에도 안 보인다). 안드로이드는 스크린 타임 같은 공식 기능이 없어 "사용 기록 접근 + 다른 앱 위에 표시 + 계속 도는 서비스"로 직접 만들어야 하고, 구글 플레이 출시 준비가 먼저다. 만들게 되면 필요한 일:

- 빌드 방법 결정: 맥에 안드로이드 빌드 도구(SDK 36, JDK 17)를 설치할지, EAS 클라우드 빌드로 할지.
- 플레이 콘솔 포그라운드 서비스 신고: 기능 설명, 서비스가 멈추면 생기는 영향, 시연 영상 링크(집중 모드 켜기 → 막힌 앱을 열면 차단 화면).
- 사용 기록 접근·다른 앱 위에 표시를 켜는 설정 화면으로 보내기 전에 앱이 직접 목적을 설명하고 동의를 받는다(구글 사용자 데이터 정책).
- 데이터 보안(Data safety) 양식은 iOS 와 같은 기준(기기 밖으로 나가는 것 없음). 대상 연령은 13세 이상.
- 접근성 API 와 `QUERY_ALL_PACKAGES` 는 쓰지 않는다. 쓰게 되면 별도 신고가 필요하다.
